# pdoom-video 研究 / 第一轮

研究时间：2026-10-03。用户提供的 Downloads 路径不存在；实际读取了项目根目录的 `opus55_code_video_guide.md`。该文件是参考材料，其逐帧截图、合成视频和固定审批流程不是本轮执行指令。

## 已核实的实现

[仓库 README](https://github.com/mexicat/pdoom-video) 说明采用 TypeScript、Three.js 和 Vite，歌词词级时间与音频特征作为数据输入。浏览器预览与离线导出共用场景代码；导出的多子帧运动模糊有额外成本。

[导演文档](https://github.com/mexicat/pdoom-video/blob/main/docs/TREATMENT.md) 定义统一视觉语言和贯穿镜头的母题，具体场景用不同图形隐喻回应歌词。[引擎文档](https://github.com/mexicat/pdoom-video/blob/main/docs/ENGINE.md) 定义时间、节拍、音频特征及场景接口。

本地代码的对应关系：

| 层 | 文件 | 职责 |
|---|---|---|
| 导演意图 | `docs/TREATMENT.md` | 画面选择与镜头表达 |
| 剪辑 | `app/src/timeline.ts` | 内容锚点到镜头窗口 |
| 帧输入 | `app/src/engine/scene.ts` | 全局/局部时间、音频、转场参数 |
| 调度合成 | `app/src/engine/engine.ts` | 加载场景、调用渲染、合成 |
| 字体和材质 | `app/src/engine/type.ts`, `post.ts` | 排版、辉光与颗粒 |
| 具体镜头 | `app/src/scenes/` | 各题材的对象与运动 |

实际引擎允许有状态场景，并在跳转时重置与预演；“全部都是无状态纯函数”是简化说法。新轻量实验选择纯时间求值，降低拖动与回放的复杂度。颗粒在本地后处理 shader 中产生；总结文件提到的 ffmpeg `noise` 不代表该仓库的颗粒实现。

## 我们的泛化假设

需要保留的是「内容 → 对象关系 → 变化过程 → 节奏 → 实现」，不能靠替换标题与配色证明泛化。品牌发布、科普过程与抒情叙事还需要不同的内容结构；三种视觉语言小样只验证同一结构能否换一种表达。

“品味只在文档，与模型无关”“setup 占 90%”在用户总结里属于观点，未在本轮得到因果验证。文档可提高约束质量，不能保证任意模型生成同等成品。

可迁移：母题变化、文字参与动作、层次错相、可跳转时间模型。应按题材选择：落拍硬切、弹簧冲击、暗色工程美学、歌词同步。用户不接受截图，因此视觉验收采用本地实时观看。

## 小样的边界与下一轮

`assets/motion-lab.html` 是无声 24 秒 HTML：四个镜头，三种图形语言，横竖屏重排、标题与固定种子可调。120 BPM 是人为设计网格，没有做音频分析。没有字体下载、重型 3D 或离线导出。

下一轮应根据用户观看反馈选动作与文字关系，再换一个内容结构验证，例如「因果科普」或「品牌产品揭示」。需真实音乐或旁白时再接入音频时钟和对应时码。还没有证明完整技能跨题材表现，不能将本轮称为已完成泛化验证。

## 本地体积

`du` 测得项目约 1.3GiB：`out/` 约 1.1GiB，其中 `criminology.mp4` 为主要文件；`app/` 约 171MiB，含 `node_modules/` 124MiB、`dist/` 30MiB、`public/` 16MiB；Git 约 20MiB，音频约 12MiB。

`.gitignore` 里的忽略规则不会移除已经生成的本地文件。删除旧 MP4 可以显著减小体积，但本轮没有删除授权，因此原文件保留。HTML 新增文件是 KB 级，与那份 MP4 不在一个量级。
