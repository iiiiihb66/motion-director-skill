# Vibe 知识大赏：Web 审片优先的制作约定

2026-11-15，根据用户本次明确说明更新。目标是持续制作美感、旁白、字幕都可靠的知识讲解；既有风格试验用于寻找和积累可复用方法。当前已有作品、预览能力和部分质量参考，整套跨主题 SOP 仍需实作验证。

## 固定质量标准，按主题组织讲解

| 层面 | 逐步固定的部分 | 每期需要调整的部分 |
| --- | --- | --- |
| 内容 | 关键论断有出处，示意与实测分清，每段有明确的理解目标 | 先讲什么、例子、解释深度、篇幅与信息释放顺序 |
| 美感 | 系列字体、配色、留白、信息层级和字幕安全区 | 主道具、图解、场景、机位，以及何时使用 2D / 3D / 真实资料 |
| 声音 | 经用户认可的音色、自然度与清晰度，人声优先的混音 | 问句、重音、语气、停顿和局部速度；以理解负担决定节奏 |
| 字幕 | 与实际口播一致，断句清楚，字号与对比度适合手机观看 | 长术语、公式和诗句如何拆分，何时额外出现关键词或标注 |
| 制作 | 同一份源工程、可定位时间轴、可重复检查和导出 | 每个知识点需要的镜头数量、场景复杂度与观察时长 |

同一账号可以形成稳定的视觉与声音辨识度。具体机理、历史故事、概念对比需要各自的讲法；模板应提供组件和组织方法，允许按理解目标组合。Three.js 与程序化建模适合空间和机制解释，其它内容可使用图解、时间线、数据图或资料画面。

## 一期内容怎样推进

1. **明确讲解目标。** 写清“观众看完能理解什么”，整理支持关键论断的资料，确定这一期讲到哪里。时长随内容复杂度安排。
2. **编排理解过程。** 按段写旁白和画面任务：观众此时要看见什么、为什么需要这一镜、要留多久。可借用猜谜、对比、因果、流程、历史线等结构。新形式或难解释的机制先验证一个 6～10 秒代表镜头；已验证形式可直接进入整期草稿。
3. **确定声音与字幕。** 音色未定时先做短试听；已认可的声音尽量复用。以实际口播时长、停顿和关键词位置生成字幕与动作时码，避免靠统一加速把内容塞进预设长度。暂无配音时可先看画面，但标明尚未完成声音审阅。
4. **生成可修改的 Web 整片。** 具备播放、暂停、重播、拖进度和按段定位。先让用户在这里看完整的讲解、配音、字幕和镜头关系；反馈能定位到具体段落或秒数。
5. **在 Web 中改到通过。** 改清楚讲法、节奏、美感、声音和字幕。用户确认的是当前具体版本；后续修改影响已审内容时，重新核对相应部分。
6. **需要视频时导出。** Web 未明确通过，不自动加入逐帧渲染队列。用户要求导出后，使用已确认版本的同一画面逻辑、时间轴与素材；检查成片的字幕、声画同步、切点和画幅，保留 Web 与源工程便于继续修改。

本项目已有 9:16 棱镜质量参考，知识短片默认按手机竖屏考虑；本期另有画幅选择时按其选择制作。预览可降低渲染分辨率，构图、内容与时间轴应保持一致。单文件或共享静态资源均可，离线可用和 M1 Air 的实际运行表现优先。

## 让修改保持便宜

用稳定的段落 ID 关联台词、声音、字幕、画面与事实来源。动作可相对某句口播的关键词安排，减少后半片依赖前半片硬编码秒数的情况。字幕和旁白共享文本来源，字幕只另存断句与样式；片中关键词属于辅助图解，不能代替完整字幕。

| 用户反馈 | 修改范围 |
| --- | --- |
| “字太小、太挤、机位不清楚” | 修改布局、字幕样式或镜头，复用既有音轨 |
| “这里没讲明白、顺序不对” | 修改对应段落的文案与呈现，检查关联事实和前后衔接 |
| “这一句声音别扭” | 优先重做该句/段声音，再更新对应字幕与动作；后续起点随段长重新计算 |
| “换主题” | 复用声音与视觉规范、播放器和已验证组件，重新组织这一期的讲解过程 |

按段修改与依赖重算是后续生产工程的实现要求，当前所有历史播放器并未统一具备这些能力。已有工作台负责作品、版本和附件管理，尚未实现自动脚本编辑、配音重生成、自动对齐或一键批量导出。

## 何时能称为稳定 SOP

先用不同结构的主题检验同一套规范，例如一个机制解释、一个步骤/结构讲解、一个概念对比。逐期记录实际反馈、修改轮数、换题时需新增什么、音色/字幕是否持续合格，以及预览运行情况。通过换题复试并由用户认可后，才将对应组件或做法列入稳定生产基线。

现有棱镜是已确认的局部质量参考；其它找回作品可作为候选。恢复成功、能播放或模型自评通过，都不自动等于用户已选定该风格。

## 与现有 Skill 的关系

`vibe-knowledge` 提供知识脚本母版、事实清单、组件和声音处理参考；本项目沿用用户明确的 Web 优先制作顺序。该 Skill 文档中的固定 BGM、默认克隆音色、固定语速/切镜频率、横屏 60fps 和模型署名，不自动成为本用户的偏好。也不为迎合“每三秒必须运动”等通用规则打断必要的观察与理解。

配音工具、模型可用性与实际费用按当次环境检查，不把旧文档中的“免费/限免”当作当前事实。此前讨论只固化目标与约定；用户随后授权继续，现已进入下述首轮 Web 试做。视频仍在 Web 审阅之后按需导出。

共用播放器、字幕、分段音轨缓存与版本校验，分别实现三种讲法：

| 案例 | 本期组织方式 | 当前状态 |
| --- | --- | --- |

入口与素材位于 `projects/vibe-pilot/`，统一目录各有一张选题卡。已实现：正文变化按段识别声音过期；画面标签变动复用既有声音；本地拼接重算后续时码；构建拒绝不匹配的旧正文/段落顺序；Web 改稿自动静音原声，可导出改稿和反馈。仍通过本地命令或后续代理执行配音，不是浏览器里的一键 API 调用。

浏览器检查、音轨响度和科学计算验证见该项目 QA 文件。自然度、审美和解释效果仍待用户判断；本轮配额不足也说明跨期生产还需评估实际声音额度，不能只按某个 Skill 的“限免”描述规划产能。
