# 动态解说工作台：整理方案与审查记录

日期：2026-11-14。日常唯一入口：[工作台](../index.html)。

2026-11-15 目标澄清：用户最终要稳定产出「Vibe 知识大赏」，之前的多风格试验用于寻找可复用的制作方法。美感、配音、字幕要形成稳定标准，知识输出节奏和呈现方式按主题调整；先在完整 Web 中审阅和修改，确认后再按需导出视频。后续制作优先遵循 [Web 审片工作流](VIBE-KNOWLEDGE-WORKFLOW.md)，不将整理目录或某种风格试做当成已完成的生产 SOP。

## 你实际要管理的东西

你希望持续制作“用画面把一个知识点讲清楚”的内容。管理单位应该是一个**选题**：观众看完要理解什么。同一题目的 2D / 3D 试做、不同配音和导出文件是它的版本或附件。模型、Skill 和引擎是制作工具，不必各自变成一个日常工作台。

现在的困难来自三个层级混在一起：

| 层级 | 应该回答的问题 | 原来的混乱 |
| --- | --- | --- |
| 选题 | 这一条要讲什么？还要不要继续？ | 每个新 HTML 看起来都是新项目 |
| 版本 | 哪一版更好？改了什么？主版本是哪一个？ | 原版、精修版、MP4 和离线包平铺，无法看出关系 |
| 工具 / 素材 | 用什么做？能否复用？ | 模型看板、拆解示例与成片混在一起 |

之前我新增了多个总览页，重复导航和数据，使你的判断更费力。这一轮把它们收敛了。

## 一个工作台的使用方法

工作台只有一个项目目录，里面提供不同工作阶段的视图：

1. **待制作**：记录题目和观众要理解的一句话。暂时不生成长片。
2. **制作中**：建议同时只做一个选题；先验证一个代表镜头，再扩展。
3. **待你审阅**：生成完成只是到了这里。你看画面、听讲解，选一个主版本并写具体下一步。
4. **定稿与参考**：满意后再移入。棱镜项目有既有确认记录，先保留为质量参考；这不代表所有项目已经发布。
5. **工具与试验**：HY4 / Gemini 短样、Cutaway 和引擎参考集中存放。技术形式在这里复试，别同时扩展成很多内容项目。
6. **历史归档**：暂时不继续的选题移到这里。归档只改变显示位置，仍能找回版本。

3D / 2D 是筛选条件。旧 `projects.html`、`3d.html` 和 `format-lab/index.html` 进入同一个工作台，不再维护三套总目录。HY4 / Gemini 和 Cutaway 原有示例页面仍是源项目资料。

每张选题卡片只有一个详情页，里面列版本和文件。当前目录合并了 **35 个选题/工具、134 个主要版本入口**。独立视频均已登记（13 个非重复视频入口）；22 个逐镜片段、3 份重复视频、QA 截图、音频中间文件留在各项目内部，不冒充新的作品卡片；已经识别为字节相同的根目录副本不重复展示。

你可以在详情中：选主版本、改阶段、记下一步、登记新生成的 HTML / MP4 相对路径。新选题也可以直接记录。登记不等于生成、复制或上传文件；手动登记的路径会标成尚未核对存在性。

整理结果保存在当前浏览器，**不自动写回仓库**。每轮整理后点“备份整理结果”保存 JSON；换浏览器用“恢复备份”。恢复会合并已知项目的整理信息，不执行备份中的代码或文件操作。导出的 JSON 可交给后续维护者审阅，再更新基础目录；目前没有自动同步服务。

## 怎样减少新的试错

复用已找到的候选画面、声音和字幕做法，用不同结构的主题验证其稳定性。既有“3D 倾向 Gemini、2D 倾向 HY4”的反馈仍作为历史观察，不当作通用模型排名；新主题以讲解需要选择呈现方式。

每次选题按下面顺序走：

> 讲解目标与资料 → 按知识结构编排旁白/画面 → 声音与字幕对齐 → 完整 Web 审片与局部修改 → 用户确认具体版本 → 按需导出与成片核对

新形式或难解释的机制可先做 6～10 秒代表镜头；已验证形式不必每次重走风格探索。跨题复试、改动依赖关系与稳定标准详见 [Vibe 制作约定](VIBE-KNOWLEDGE-WORKFLOW.md)。

不要因为一次结果不满意就新建工作台、重新换整套 Skill 或同时生成多个长版本。先指出具体问题：解释不清、镜头没信息、模型不像、声音机械、字幕太多、节奏太慢。一次只改一两个维度，版本说明写清改动。

每个版本建议登记四件事：改了什么、网页文件、是否有对应 MP4、你看完的判断。后续新增选题可采用 `projects/<选题>/versions/<版本>/` 保存源文件、预览、配音和检查记录；**现有工程本轮不整体搬家**，以免弄断相对路径。探索短样仍可留在 `format-lab/`，通过目录登记关联。
